v30: the transparency slider now has an Opacity label. The toggle turns the see-through effect on; the slider sets how solid the popup is, so 72% means 72% opaque, which the old unlabelled slider under a "Transparency" heading read as the opposite. The stored value and its meaning are unchanged (alpha = setting / 100), so existing configs need no migration. v31: the description now says "the widget when it's open" instead of "the panel" (in Plasma, "panel" means the taskbar, which the Panel Icon section below is about). "Popup" was tried in v30 and dropped: to users it reads as ads or notifications. "Widget" is the word Plasma shows users ("Add Widgets…"), and "when it's open" separates the expanded remote from its panel icon.
Preview (v27–v29): no frame; it sits in the row like any other control, and the "Preview" label is what marks it as a sample. It's right-aligned like the switch and segmented control above, so the glyph is always flush with the right edge: turning the number off removes it and the glyph takes its place. In QML that's plain visible on the label inside a right-anchored RowLayout. (v27 tried a fixed-size framed tile so nothing moved; once the frame was gone, the reserved space just left the glyph floating.)
New in v26: Panel Icon section, between Appearance and Volume. Two settings, matching devialet_panel_icon_mockup_v7: Icon style (Dial / Level) uses the same segmented control as Volume step size, with each option led by a small copy of its glyph so the choice is visible before you make it; the glyph follows the label's dim/copper colour. Show volume next to icon is the existing copper switch; the description says up front that vertical panels always hide the number, so nobody wonders why the setting "doesn't work" there. There is deliberately no setting for which side the number sits on.
The Preview line shows the result live, at real panel size, in this page's own text colour. In the real implementation it should instantiate the same glyph component the panel uses rather than a copy, so the two can't drift. It's an optional extra: the section works without it if it turns out to be awkward in a KCM page.
Defaults for both settings (Dial, number on) are placeholders for you to decide; Restore defaults resets them to whatever you pick.
Minor fix: Restore defaults in v25 found the step-size buttons by position on the page, so adding any segmented control above them would have reset the wrong one. The step and icon-style controls now have their own ids.
Copper = our General page, fully custom-drawn QML (own switches/sliders, own type), matched against your real Darkly window background rather than an invented palette.
Window titlebar (gear/pin left, chevron-down/chevron-up/X right), sidebar chrome + blue selection color, and the Shortcuts/About page content are Plasma's — sampled from your screenshot so the window as a whole reads as one native piece, with our page as the one that happens to have personality.
Keyboard Shortcuts and About icons are now hand-redrawn approximations of your real icon theme's glyphs (keyboard+gear badge, solid blue "i" circle) rather than the generic placeholders used in earlier versions — close, but not a pixel-perfect extraction of the actual SVG assets, since I don't have access to your icon theme's source files.
Volume limits use +/− steppers rather than a slider — interdependent thresholds sharing one slider track gets visually cramped and easy to mis-drag, whereas a stepper gives exact, unambiguous values. Min-above-hard shows an inline warning as a placeholder for real validation. Stepper bounds are the real Expert Pro line range (−96 to 0 dB). Holding a +/− button repeats at 100ms after a short initial delay, same cadence as the flyout's own volume buttons. Minimum volume trims the unused low end of the slider's range rather than acting as a safety ceiling — it's a usability control, not a protection one. Soft limit removed in this version, per request — Hard limit is now the only ceiling.
Defaults moved into the page content (new "Reset" section, bottom of General) rather than the footer — the ConfigDialog's Cancel/Apply/OK bar is fixed native chrome, not something a plasmoid's config.qml can add buttons to. This is option 2 from the Claude Code research: keeps the existing ConfigGeneral.qml/KCM page and its Apply/OK flow as-is, at the cost of not matching the original footer-button mockup exactly.
Chime sound is now a three-way choice, not a single file picker — collapsing it to "pick a file" would quietly break the thing Phase 10.1.0 got right after a real by-ear correction: the chime should track your desktop's own configured sound theme by default, not a fixed file. System theme (the default, matching the shipped 10.1.0 behavior) is deliberately NOT an editable control — it's a status line naming the currently-resolved theme, because there's nothing to configure in this mode; it just tracks kdeglobals live. Choose theme pins the chime to one specific installed theme regardless of your desktop setting, via a dropdown — real implementation would enumerate installed themes the same way `SoundThemeConfig` (per Phase 10.0.0's report) already does, not a hardcoded list like this mockup's four placeholder entries. Custom file is the original filename chip + Browse + Preview, unchanged, for anyone who wants a sound unrelated to any installed theme. Preview briefly pulses rather than playing actual audio in all three modes, since no sound file exists in this static mockup.
